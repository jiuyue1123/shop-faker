# 交易域数据标准说明书 V1.0

本说明书定义交易域各实体的字段构成、类型约束与边界口径，是建表、数据生成与数据接入的统一依据。

## 1. 适用范围

本文件覆盖交易域 12 个实体：

| 实体 | 说明 |
|---|---|
| `user` | 用户主档 |
| `user_address` | 用户收货地址 |
| `shop` | 店铺 |
| `category` | 商品类目树 |
| `product` | 商品 SPU |
| `sku` | 商品 SKU |
| `cart` | 购物车 |
| `order` | 订单主表 |
| `order_item` | 订单明细 |
| `payment` | 支付流水 |
| `refund` | 退款单 |
| `logistics` | 物流单 |

不在本文件范围内的内容：

- 用户行为埋点事件的字段定义，见《行为埋点标准口径说明书 V1.0》
- 营销与会员域实体（优惠券、促销活动、积分流水）
- 库存与价格变更流水
- 具体的建表语句。DDL 由生成器的 `dump-sql` 子命令按本文件产出

**与其他文档的关系**：本文件与《行为埋点标准口径说明书 V1.0》在字段定义、类型或取值上出现冲突时，以本文件为准。埋点报文的字段映射见第 9 节。

## 2. 设计原则

1. **单一解释**：每个字段只有一种解释，避免建表方、生成方与消费方理解不一致。
2. **贴合真实业务**：字段构成以真实电商系统的实现为准，不设业务上不存在的字段。
3. **边界明确**：讲清楚取值范围、为空语义与业务约束。
4. **可复现**：给定随机种子，按本文件能生成完全一致的数据。
5. **可校验**：每个实体都能写出明确的校验规则，见第 7 节。

## 3. 命名与类型规范

### 3.1 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 表名 | 小写 snake_case，单数名词 | `user`、`order_item` |
| 字段名 | 小写 snake_case | `order_amount`、`register_time` |
| 主键 | `{实体}_id` | `user_id`、`order_id` |
| 外键 | 与被引用表主键同名 | `order.shop_id` 引用 `shop.shop_id` |
| 布尔字段 | `is_` 或 `has_` 前缀 | `is_default`、`is_leaf` |
| 时间字段 | `_time` 后缀 | `pay_time`、`add_time` |
| 金额字段 | `_amount` 或 `_price` 后缀 | `pay_amount`、`sale_price` |

命名变更等同于新增字段。字段上线后禁止原地改名，需要更换命名时新增字段并保留旧字段的过渡期。

### 3.2 类型规范

| 类别 | 类型 | 规则 |
|---|---|---|
| 主键 | `BIGINT` | 由生成器统一分配，全局唯一。实体的唯一标识，内部关联与对外引用均使用该字段 |
| 外键 | `BIGINT` | 必须指向被引用表的主键，不允许为 `0` 或负数 |
| 金额 | `DECIMAL(18,2)` | 单位元，非负，禁止使用浮点类型，禁止字符串 |
| 时间 | `DATETIME` | 精确到毫秒，统一按东八区存储，字段本身不带时区后缀 |
| 日期 | `DATE` | 仅用于生日等无时间成分的场景 |
| 布尔 | `TINYINT(1)` | 仅取 `0` 或 `1`，禁止 `NULL`，禁止用其他数值代替 |
| 枚举 | `TINYINT` | 取值见第 6 节，禁止用字符串存枚举 |
| 字符串 | `VARCHAR` | 字符集 `utf8mb4`，长度按字段表指定 |
| 结构化数据 | `JSON` | 仅用于规格、快照等无固定结构的字段 |

金额与时间的口径与《行为埋点标准口径说明书 V1.0》一致：金额单位为元、保留两位小数，时间统一东八区。

实体不设独立的业务编号字段。主键即实体的唯一标识，对外展示与埋点上报均使用主键，不存在第二套编号。

### 3.3 通用审计字段

每张表必须包含以下两个字段：

| 字段 | 含义 | 类型 | 必填 | 取值与格式 | 边界与说明 | 示例 |
|---|---|---|---|---|---|---|
| `created_at` | 记录写入时间 | DATETIME | 是 | 精确到毫秒 | 数据落库时刻，与业务时间无关，见第 8 节 | `2026-10-02 12:00:00.000` |
| `updated_at` | 记录最后变更时间 | DATETIME | 是 | 精确到毫秒 | 不小于 `created_at`，无变更时等于 `created_at` | `2026-10-02 12:00:00.000` |

## 4. 实体总览

| 实体 | 中文名 | 粒度 | 主键 | 主要外键 |
|---|---|---|---|---|
| `user` | 用户 | 一行一个用户 | `user_id` | — |
| `user_address` | 收货地址 | 一行一个地址 | `address_id` | `user_id` |
| `shop` | 店铺 | 一行一个店铺 | `shop_id` | `main_category_id` |
| `category` | 类目 | 一行一个类目节点 | `category_id` | `parent_id` |
| `product` | 商品 SPU | 一行一个商品 | `product_id` | `shop_id`、`category_id` |
| `sku` | 商品 SKU | 一行一个规格 | `sku_id` | `product_id` |
| `cart` | 购物车 | 一行一个用户的一个 SKU | `cart_id` | `user_id`、`shop_id`、`product_id`、`sku_id` |
| `order` | 订单 | 一行一个订单 | `order_id` | `user_id`、`shop_id`、`address_id` |
| `order_item` | 订单明细 | 一行一个订单内 SKU | `item_id` | `order_id`、`product_id`、`sku_id` |
| `payment` | 支付流水 | 一行一次支付 | `payment_id` | `order_id` |
| `refund` | 退款单 | 一行一次退款申请 | `refund_id` | `order_id`、`payment_id` |
| `logistics` | 物流单 | 一行一个订单的物流 | `delivery_id` | `order_id` |

关联关系：

```
user ──< user_address
user ──< cart >── shop
              │
              └── sku ──< product >── shop
user ──< order >── shop
              │
              ├──< order_item >── product、sku
              ├──< payment
              ├──< refund
              └──< logistics
```

`order` 与 `product`、`sku` 通过 `order_item` 关联，不存在直接外键。`cart` 为用户与 SKU 的关联表。

## 5. 实体详细口径

各字段表中：

- **必填**列取值 `是` 表示该字段为 `NOT NULL`；`否` 表示允许 `NULL`。
- 允许 `NULL` 的字段表示业务上尚未发生或未知，不得用 `0`、`''` 或占位值代替。
- 枚举字段的取值集中列在第 6 节，字段表中只标注枚举含义。

| `order_source` | 下单入口 | TINYINT | 是 | 枚举 `order_source` | 与埋点 `order_submit.source` 对应，见第 9 节 | `1` |
| `pay_time` | 支付时间 | DATETIME | 否 | 精确到毫秒 | 未支付为 `NULL`，不得早于 `order_time` | `2026-10-02 12:00:05.000` |

## 7. 业务不变量与校验规则

以下规则是交易域数据的硬约束，生成后必须逐条校验通过。

### 7.1 引用完整性

| 规则 | 说明 |
|---|---|
| 外键存在 | 每个外键值都必须能在被引用表中找到对应的主键 |
| 外键归属 | `order.address_id` 指向的地址必须属于 `order.user_id`；`refund.payment_id` 指向的流水必须属于 `refund.order_id`；`order_item.sku_id` 指向的 SKU 必须属于 `order_item.product_id`；`cart.shop_id`、`cart.product_id` 必须与 `cart.sku_id` 的归属一致 |
| 主键唯一 | 所有 `{实体}_id` 在全表内唯一 |
| 其他唯一约束 | `user.username`、`user.phone`、`payment.trade_no`、`logistics.tracking_no` 全局唯一；`sku.sku_code` 在同一商品下唯一；`shop.shop_name` 在同一商家下唯一 |
| 基数约束 | 一个订单最多一条 `logistics`；同一用户同一 SKU 最多一条 `status = 1` 的 `cart` |

### 7.2 金额闭合

订单金额必须同时满足以下等式，任一条不成立即为脏数据：

1. `order_item.item_amount = order_item.unit_price * order_item.quantity`
2. `order.order_amount = Σ order_item.item_amount`（同一 `order_id` 下）
3. `order.discount_amount = Σ order_item.discount_amount`（同一 `order_id` 下）
4. `order.pay_amount = order.order_amount - order.discount_amount + order.freight_amount`
5. `order.paid_amount = Σ payment.pay_amount`（同一 `order_id` 下 `pay_status = 1` 的流水）
6. `order.paid_amount <= order.pay_amount`
7. `refund.refund_amount <= order.paid_amount`

### 7.3 状态机

**订单状态**：

```
10 待付款 ──支付成功──> 20 已付款 ──发货──> 30 已发货 ──签收──> 40 已签收
    │                      │
    └──取消/超时──> 50 已取消   └──申请退款──> 60 退款中 ──退款完成──> 70 已退款
```

**退款状态**：

```
10 待审核 ──> 20 已同意 ──> 40 退款中 ──> 50 已退款
    │
    └──驳回──> 30 已拒绝
```

**物流状态**：

```
10 待揽收 ──> 20 运输中 ──> 30 派送中 ──> 40 已签收
                  │
                  └──异常──> 50 异常 ──> 20 运输中（恢复）
```

**跨实体状态一致性**：

| 规则 | 说明 |
|---|---|
| 订单与物流 | `order_status` 为 `30` 或 `40` 时必须有对应 `logistics`；`order_status` 为 `40` 时 `logistics.delivery_status` 必须为 `40` |
| 订单与退款 | `order_status` 为 `60` 或 `70` 时必须有对应 `refund` |
| 订单与支付 | `order_status` 不为 `10`、`50` 时必须有成功流水；`order_status` 为 `10` 或 `50` 时不得有成功流水 |
| 退款与支付 | `refund` 必须关联到状态为成功的 `payment` |
| 购物车与订单 | `cart.status` 为 `2` 的记录，其 `user_id` 与 `sku_id` 必须能在同一用户的 `order_source = 1` 的订单明细中找到；`order_source = 1` 的订单，其明细必须来自该用户 `status = 2` 的购物车记录 |

### 7.4 时间单调性

同一业务链路内的时间戳必须单调不减：

| 链路 | 约束 |
|---|---|
| 用户下单 | `user.register_time <= order.order_time` |
| 地址可用 | `user_address.created_at <= order.order_time` |
| 商品在售 | `product.on_shelf_time <= order.order_time`，`sku.created_at <= order.order_time` |
| 店铺开业 | `shop.open_time <= product.on_shelf_time` |
| 加入购物车 | `user.register_time <= cart.add_time` |
| 购物车转订单 | `cart.add_time <= order.order_time`（`order_source = 1` 时） |
| 订单支付 | `order.order_time <= order.pay_time` |
| 订单取消 | `order.order_time <= order.cancel_time` |
| 退款申请 | `order.pay_time <= refund.apply_time` |
| 退款完成 | `refund.apply_time <= refund.finish_time` |
| 物流发货 | `order.pay_time <= logistics.ship_time` |
| 物流签收 | `logistics.ship_time <= logistics.receive_time` |

### 7.5 状态与时间字段一致

| 规则 | 说明 |
|---|---|
| 已付款及之后 | `order_status` 不为 `10`、`50` 时，`pay_time` 必须非空 |
| 已取消 | `order_status` 为 `50` 时，`cancel_time` 与 `cancel_type` 必须非空，且 `paid_amount = 0` |
| 未取消 | `order_status` 不为 `50` 时，`cancel_time` 与 `cancel_type` 必须为空 |
| 已签收 | `logistics.delivery_status` 为 `40` 时，`receive_time` 必须非空 |
| 未签收 | `logistics.delivery_status` 不为 `40` 时，`receive_time` 必须为空 |
| 退款终态 | `refund_status` 为 `30` 或 `50` 时，`finish_time` 必须非空 |
| 商品下架 | `product_status` 不为 `1` 时，`off_shelf_time` 必须非空 |

### 7.6 取值范围

| 规则 | 说明 |
|---|---|
| 金额非负 | 所有金额字段取值不小于 `0` |
| 数量 | `order_item.quantity >= 1`，`cart.quantity >= 1` |
| 评分 | `shop.rating` 落在 `[0.00, 5.00]` |
| 价格关系 | `sku.cost_price <= sku.sale_price` |
| 年龄 | 由 `birthday` 推算的年龄落在 `[14, 90]`，且不晚于当前日期 |
| 层级 | `category.level` 落在 `[1, 3]`，且与 `path` 的分段数一致 |
| 英文长度 | `currency` 固定为三位大写字母 |
| 枚举合法 | 所有枚举字段的取值必须存在于第 6 节 |

### 7.7 脱敏与唯一性交叉约束

| 规则 | 说明 |
|---|---|
| 手机号唯一 | `user.phone` 全局唯一。脱敏后的值同样唯一，脱敏不得破坏唯一性 |
| 脱敏一致性 | 同一手机号在所有出现位置的脱敏结果一致 |
| 默认地址唯一 | 同一 `user_id` 下 `is_default = 1` 的记录最多一条 |
| 默认地址存在 | 产生过订单的用户至少有一条 `status = 1` 的地址 |

## 8. 易混淆字段对照表

| 易混淆对 | 区别 |
|---|---|
| `order.order_amount` vs `pay_amount` vs `paid_amount` | 商品总额（优惠前）vs 应付金额（算入优惠与运费）vs 实付金额（实际收款，未支付为 0） |
| `order.discount_amount` vs `order_item.discount_amount` | 订单级优惠总额 vs 分摊到单个明细的优惠，前者等于后者之和 |
| `order_item.unit_price` vs `order_item.item_amount` | 单价 vs 单价乘数量 |
| `order_item.unit_price` vs `sku.sale_price` | 下单时的价格快照 vs 当前售价，商品调价后两者不同 |
| `cart.add_price` vs `sku.sale_price` | 加购时的价格快照 vs 当前售价 |
| `product.list_price` vs `sku.sale_price` | 商品层面的标价 vs 规格层面的实际售价 |
| `sku.sale_price` vs `sku.cost_price` | 售价 vs 成本价，后者不高于前者 |
| `sku.sku_code` vs `sku.sku_id` | 商家侧自有编码 vs 系统主键 |
| `order.order_time` vs `pay_time` vs `cancel_time` | 下单时间 vs 支付时间 vs 取消时间 |
| `logistics.ship_time` vs `receive_time` | 发货时间 vs 签收时间 |
| `order.order_status` vs `logistics.delivery_status` | 订单维度状态（含未支付、已取消）vs 物流维度状态（仅覆盖发货之后） |
| `user.register_time` vs `user.created_at` | 业务上的注册时间 vs 该行数据写入数据库的时间 |
| `user.phone` vs `user_address.receiver_phone` | 账号绑定手机号 vs 单个收货地址的联系电话，可以不同 |
| `category.parent_id` vs `NULL` | 顶级类目的父节点固定为 `0`，不使用 `NULL` |
| `order.cancel_time` vs `refund.finish_time` | 未支付订单的取消时间 vs 已支付订单退款完成的时间 |
