# 行为埋点标准口径说明书 V1.0

本说明书定义行为埋点的事件类型、触发时机、属性结构与边界口径，是埋点开发、验收与数据接入的统一依据，同时也是 shop-faker 生成行为埋点数据的字段依据。

## 1. 适用范围

本文件覆盖：

- 事件类型（`eventType`）枚举与命名规范
- 每个事件的触发时机与不触发条件
- 事件属性（`properties`）的字段、类型、枚举与边界
- 上报报文结构、上报策略与重试口径
- 埋点验收用例与上线后数据校验规则

业务实体（用户、收货地址、店铺、类目、商品、SKU、购物车、订单、订单明细、支付、退款、物流）的字段定义见《交易域数据标准说明书 V1.0》，本文件不重复定义。

**与其他文档的关系**：本文件与《交易域数据标准说明书 V1.0》在字段定义、类型或取值上出现冲突时，以数据标准说明书为准。埋点字段与交易域实体的对应关系见数据标准说明书第 9 节。

## 2. 设计原则

1. **业务可解释**：每个事件对应一个可向业务方解释的用户动作，禁止为采集而采集。
2. **一次动作一条事件**：用户完成一个完整动作后生成且仅生成一条事件，禁止在动作进行中重复记录。事件不立即发送，按第 8 节的缓存与批量策略发送。
3. **事件与属性分离**：稳定的公共上下文放 `baseInfo`，随事件变化的业务字段放 `properties`，两者不重叠。
4. **端侧一致**：Web、iOS、Android、小程序同一事件的 `eventType`、触发时机、属性命名完全一致。
5. **可回溯**：仅凭埋点数据能够还原用户的完整行为序列与漏斗路径。
6. **可校验**：每个事件都能写出明确的触发与不触发用例，用于自动化验收。

## 3. 事件命名规范

`eventType` 统一采用小写 snake_case，格式为 `{对象}_{动作}`。

| 部分 | 取值 |
|---|---|
| 对象 | `app`、`page`、`product`、`button`、`search`、`favorite`、`cart`、`order` |
| 动作 | `launch`、`exit`、`view`、`leave`、`expose`、`click`、`submit`、`add`、`remove`、`share`、`pay`、`cancel`、`refund` |

约束：

- 禁止拼音命名、驼峰命名、大小写混用。
- 同一动作在全平台只保留一种写法，不允许出现 `product_view` 与 `productView` 并存。
- 命名变更等同于新增事件。事件上线后禁止原地改名，需要更换命名时新建事件并废弃旧事件，废弃事件保留至少一个版本周期的双写。
- `eventName` 为中文展示名，仅用于报表与埋点管理平台展示，不参与任何计算逻辑，端侧禁止依据 `eventName` 做分支判断。

## 4. 上报结构

一次上报 = **1 个 `baseInfo` + N 个 `eventInfo`**。

```json
{
  "baseInfo": { ... },
  "eventInfo": [ { ... }, { ... } ]
}
```

禁止使用「一个 `baseInfo` + 一个 `eventInfo` 对象」的单事件结构，统一为数组。

**时间字段的归属**：`baseInfo` 中只有 `sendTime`，表示**报文发送时间**，一次上报只有一个，取报文发出时刻的值。每个事件的**发生时间**由各自 `eventInfo.eventTime` 承载。同一次上报内的多个事件可以有各自不同的 `eventTime`，禁止用 `sendTime` 代替事件时间，也禁止在 `baseInfo` 中携带任何事件时间字段。

### 4.1 baseInfo 公共字段

`baseInfo` 承载一次上报中所有事件共享的上下文。字段随每条事件一并落库。

| 分类 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 终端 | `platform` | string | 客户端类型，枚举：`app`、`h5`、`mini_program`、`pc` |
| 终端 | `deviceId` | string | 设备唯一标识，长期持久，卸载重装或清缓存可能变化；不是用户 ID，不随登录变化 |
| 终端 | `viewportHeight` | number | 网页可见区高度，px，整数；非 Web 端传 `0` |
| 终端 | `viewportWidth` | number | 网页可见区宽度，px，整数；非 Web 端传 `0` |
| 终端 | `screenWidth` | number | 屏幕物理分辨率宽度，px，整数 |
| 终端 | `screenHeight` | number | 屏幕物理分辨率高度，px，整数 |
| 终端 | `screenColorDepth` | number | 屏幕调色板比特深度，bit；非 Web 端传 `0` |
| 终端 | `screenPixelDepth` | number | 屏幕像素深度，bit；非 Web 端传 `0` |
| 终端 | `browserName` | string\|null | 浏览器名称；非 Web 端传 `null` |
| 终端 | `browserPlatform` | string\|null | 浏览器平台环境；非 Web 端传 `null` |
| 应用 | `appId` | string | 应用 ID，由数据平台分配 |
| 应用 | `appCode` | string | 应用编码，业务唯一标识，不随版本变化 |
| 应用 | `appName` | string | 应用名称，多端保持一致 |
| 应用 | `appVersion` | string | 应用版本，语义化版本 |
| 应用 | `pluginVersion` | string | 采集 SDK 版本 |
| 用户 | `userId` | string\|null | 登录用户 ID，退出登录后置 `null`；未登录必须为 `null`，禁止用 `deviceId` 冒充 |
| 用户 | `sessionId` | string | 会话唯一标识，会话内所有事件复用，切分规则见 4.2 |
| 环境 | `userIp` | string\|null | 用户 IP，优先由服务端从请求头获取 |
| 位置 | `longitude` | number\|null | 经度，范围 `-180 ~ 180`；与 `latitude` 必须成对出现 |
| 位置 | `latitude` | number\|null | 纬度，范围 `-90 ~ 90`；与 `longitude` 必须成对出现 |
| 位置 | `coordinateSystem` | string\|null | 坐标系，枚举：`WGS84`、`GCJ02`、`BD09`；经纬度非空时必填 |
| 位置 | `accuracy` | number\|null | 定位精度，单位米，越小越准 |
| 位置 | `geoSource` | string\|null | 定位来源，枚举：`gps`、`network`、`ip`、`cache`、`manual` |
| 位置 | `locationTime` | string\|null | 定位时间，ISO 8601 带时区 |
| 时间 | `sendTime` | string | 本次上报包的**发送时间**，即报文发出时刻，ISO 8601 带时区。不是事件发生时间，事件时间见 `eventInfo.eventTime`。`baseInfo` 不承载任何事件时间 |
| 扩展 | `extensions` | object | 公共扩展信息，不放事件私有属性 |

位置字段约束：

- 经纬度属于敏感个人信息，须用户授权后采集，且仅在有业务场景时采集，禁止全量、高频、无目的采集。
- 坐标系默认约定为 `WGS84`。同一份数据中不允许混用坐标系而不标记。
- `geoSource` 为 `ip` 时仅表示城市级粗定位，不得当作精确经纬度使用。

### 4.2 sessionId 切分规则

**定义**：用户一次连续活跃期间共享同一个 `sessionId`。

| 场景 | 是否换会话 |
|---|---|
| 首次启动应用或打开页面 | 是，新建会话 |
| 距上次事件超过 30 分钟后的首次操作 | 是，新建会话 |
| 用户主动退出后再次进入 | 是，新建会话 |
| 页面间跳转 | 否 |
| 切换至后台不超过 30 分钟 | 否 |
| 同一标签页内刷新 | 否 |
| 关闭应用超过 30 分钟后再打开 | 是，新建会话 |
| 手动清除本地存储 | 是，新建会话 |

实现要求：会话状态存内存与本地存储，每次事件更新 `lastActiveTime`；事件触发时判断 `now - lastActiveTime > 30min`，成立则生成新 `sessionId`。超时时间可配置，各端必须一致。

### 4.3 eventInfo 字段

| 字段 | 含义 | 类型 | 说明 |
|---|---|---|---|
| `eventId` | 事件唯一 ID | string | 全局唯一，服务端据此幂等去重 |
| `eventType` | 事件类型 | string | 取值见第 5 节，小写 snake_case |
| `eventName` | 事件中文名 | string | 仅展示用，不参与逻辑 |
| `eventTime` | 事件实际发生时间 | string | 必填，每个事件各带一个，ISO 8601 带时区。与 `baseInfo.sendTime` 区分：一次上报的多个事件 `eventTime` 可以各不相同，批量补传时 `eventTime` 仍为原始发生时间 |
| `properties` | 事件属性 | object | 结构随 `eventType` 变化，定义见第 6 节 |

## 6. 事件详细口径

本节的**触发时机**指事件被生成并写入本地缓存的时刻，不等于发送到服务端的时刻。发送时机由第 8 节的缓存与批量策略决定。全文中「记录」指生成事件并写入缓存，「发送」指将缓存中的事件组成报文提交到服务端，两者不得混用。

各事件的 `properties` 属性表中：

- **必填**列取值 `是` 表示该属性缺失时该条埋点视为无效，端侧不得记录；`否` 表示可缺省。
- **为空处理**列定义属性可缺省时应当写入的值，禁止用空字符串 `""` 代替 `null`。

### 6.1 app_launch 应用启动

**触发时机**：应用进程完成初始化（含 SDK 就绪）后立即记录一条；应用从后台恢复到前台时再记录一条。

**不触发**：应用在后台被系统回收、用户未产生任何前台可见行为时不记录。

**属性**：

| 属性 | 含义 | 类型 | 必填 | 取值与格式 | 边界与说明 | 为空处理 | 示例 |
|---|---|---|---|---|---|---|---|
| `launchType` | 启动类型 | string | 是 | 枚举：`cold`、`warm` | `cold` 为进程首次启动，`warm` 为后台恢复 | 不允许为空 | `cold` |
| `isFirstLaunch` | 是否首次启动 | boolean | 是 | `true` / `false` | 以设备维度判断，卸载重装后重新计为首次 | 不允许为空 | `false` |
| `launchDuration` | 启动耗时 | number | 否 | 毫秒，整数 | 仅 `cold` 有意义；`warm` 传 `null` | 允许 `null` | `820` |
| `launchScene` | 启动场景 | string | 否 | 枚举：`icon`、`push`、`deeplink`、`share`、`other` | 用于区分自然启动与外部唤起 | 未知传 `null` | `push` |

```json
{ "launchType": "cold", "isFirstLaunch": false, "launchDuration": 820, "launchScene": "icon" }
```

### 6.2 app_exit 应用退出

**触发时机**：用户主动关闭应用、退出登录并关闭应用时记录。

**不触发**：应用切至后台不算退出；进程被系统强杀时无法保证缓存中的数据被成功发送，允许丢失，丢失率纳入数据质量监控。

**属性**：

| 属性 | 含义 | 类型 | 必填 | 取值与格式 | 边界与说明 | 为空处理 | 示例 |
|---|---|---|---|---|---|---|---|
| `exitType` | 退出方式 | string | 是 | 枚举：`user_close`、`logout`、`system_kill` | `system_kill` 仅在能被捕获时记录 | 不允许为空 | `user_close` |
| `stayDuration` | 本次会话停留时长 | number | 是 | 毫秒，整数 | 从 `app_launch` 到退出的总时长，含后台时间 | 不允许为空 | `1840000` |

```json
{ "exitType": "user_close", "stayDuration": 1840000 }
```

### 6.3 page_view 页面浏览

**触发时机**：页面渲染完成且对用户可见时记录一条。

**不触发**：页面加载失败、白屏、预加载但用户未实际看到时不记录。同一 `pageId` 连续两次 `page_view` 之间必须有一次 `page_leave` 分隔。

**属性**：

| 属性 | 含义 | 类型 | 必填 | 取值与格式 | 边界与说明 | 为空处理 | 示例 |
|---|---|---|---|---|---|---|---|
| `pageId` | 页面标识 | string | 是 | 小写 snake_case | 全局唯一，与 `pageName` 一一对应 | 不允许为空 | `product_detail` |
| `pageName` | 页面中文名 | string | 是 | 中文 | 仅展示用 | 不允许为空 | `商品详情页` |
| `pageUrl` | 页面地址 | string | 否 | 完整 URL | 必须去除 `token`、`phone` 等敏感查询参数 | 非 Web 端传 `null` | `https://example.com/product/12345` |
| `referrerPageId` | 来源页面标识 | string | 否 | 同 `pageId` 规范 | 站外进入或首个页面传 `null` | 允许 `null` | `search_result` |
| `pageType` | 页面类型 | string | 否 | 枚举：`home`、`list`、`detail`、`cart`、`order`、`user`、`other` | 用于跨页面聚合分析 | 未知传 `null` | `detail` |

```json
{ "pageId": "product_detail", "pageName": "商品详情页", "pageUrl": "https://example.com/product/12345", "referrerPageId": "search_result", "pageType": "detail" }
```

### 6.4 page_leave 页面离开

**触发时机**：用户离开当前页面时记录，与 `page_view` 成对出现。

**离开的定义**：跳转到其他页面、关闭页面或标签页、切至后台、会话超时结束，四种情形均触发。

**属性**：

| 属性 | 含义 | 类型 | 必填 | 取值与格式 | 边界与说明 | 为空处理 | 示例 |
|---|---|---|---|---|---|---|---|
| `pageId` | 页面标识 | string | 是 | 同 `page_view` | 必须与配对的 `page_view.pageId` 一致 | 不允许为空 | `product_detail` |
| `pageUrl` | 页面地址 | string | 否 | 完整 URL | 同 `page_view` | 非 Web 端传 `null` | `https://example.com/product/12345` |
| `stayDuration` | 页面停留时长 | number | 是 | 毫秒，整数 | 从 `page_view` 记录时刻起算，切后台期间不计入 | 不允许为空 | `18500` |
| `leaveType` | 离开方式 | string | 是 | 枚举：`navigate`、`close`、`background`、`session_timeout` | `session_timeout` 表示因超过 30 分钟无事件被动结束 | 不允许为空 | `navigate` |

```json
{ "pageId": "product_detail", "pageUrl": "https://example.com/product/12345", "stayDuration": 18500, "leaveType": "navigate" }
```

### 6.5 product_expose 商品曝光

**触发时机**：商品卡片在可视区域内可见面积达到阈值且持续时长达标时记录一条。

**阈值**：默认可见面积占比不低于 50%、持续不低于 500ms，两项均为可配置项，各端必须保持一致。

**不触发**：仅渲染进容器但从未进入可视区；同一卡片在同一可视区域滚动过程中反复进出，在 5 秒内只记录一条。

**属性**：

| 属性 | 含义 | 类型 | 必填 | 取值与格式 | 边界与说明 | 为空处理 | 示例 |
|---|---|---|---|---|---|---|---|
| `productId` | 商品 SPU 标识 | string | 是 | 字符串，非数字 | 见 7.2 标识类属性规范 | 不允许为空 | `88001` |
| `skuId` | 商品 SKU 标识 | string | 否 | 字符串 | 卡片未区分规格时传 `null` | 允许 `null` | `12345` |
| `shopId` | 店铺标识 | string | 是 | 字符串 | — | 不允许为空 | `2001` |
| `categoryId` | 类目标识 | string | 否 | 字符串 | 卡片展示类目时填写 | 未知传 `null` | `1001` |
| `position` | 曝光位置 | string | 是 | 格式 `{模块}_{序号}` | 序号从 1 开始，见 7.6 | 不允许为空 | `recommend_1` |
| `traceId` | 推荐请求标识 | string | 是 | 字符串 | 用于关联推荐算法请求与结果，非推荐位生成随机值 | 不允许为空 | `tr_9f2c1a` |
| `pageId` | 所在页面标识 | string | 是 | 同 `page_view` | — | 不允许为空 | `home` |

```json
{ "productId": "88001", "skuId": "12345", "shopId": "2001", "categoryId": "1001", "position": "recommend_1", "traceId": "tr_9f2c1a", "pageId": "home" }
```

| `currency` | 币种 | string | 是 | ISO 4217 三位大写 | — | 不允许为空 | `CNY` |
| `payMethod` | 支付方式 | string | 是 | 枚举：`wechat_pay`、`alipay`、`bank_card`、`balance`、`other` | 枚举由服务端下发 | 不允许为空 | `wechat_pay` |
| `tradeNo` | 支付渠道流水号 | string | 是 | 字符串 | 用于与渠道对账，服务端记录时必须填写 | 端侧记录允许 `null` | `4200001234202610021234567890` |
| `payTime` | 支付成功时间 | string | 是 | ISO 8601 带时区 | 业务时间；`eventTime` 为埋点记录时间，两者可能相差数秒 | 不允许为空 | `2026-10-02T12:00:05+08:00` |

`eventTime` 与 `payTime` 的关系：正常发送时两者接近，补传或服务端延迟发送时 `payTime` 可能明显早于 `eventTime`，分析时应以 `payTime` 为准。

```json
{
  "orderId": "9000001",
  "payAmount": 698.00,
  "currency": "CNY",
  "payMethod": "wechat_pay",
  "tradeNo": "4200001234202610021234567890",
  "payTime": "2026-10-02T12:00:05+08:00"
}
```

### 6.17 order_cancel 订单取消

**触发时机**：订单取消成功后记录，包含用户主动取消与系统自动取消。

**边界**：超时未支付由系统自动取消的订单同样记录，`cancelType` 传 `timeout`；已支付订单的售后流程不计入本事件，走 `order_refund`。

**属性**：

| 属性 | 含义 | 类型 | 必填 | 取值与格式 | 边界与说明 | 为空处理 | 示例 |
|---|---|---|---|---|---|---|---|
| `orderId` | 订单标识 | string | 是 | 字符串 | — | 不允许为空 | `9000001` |
| `cancelType` | 取消方式 | string | 是 | 枚举：`user`、`timeout`、`system` | `system` 表示风控或库存等系统原因 | 不允许为空 | `user` |
| `cancelReason` | 取消原因 | string | 否 | 枚举：`no_need`、`wrong_item`、`price_change`、`out_of_stock`、`other` | 系统取消时可为枚举外的原因码，需同步至服务端枚举表 | 未知传 `null` | `wrong_item` |
| `cancelAmount` | 取消金额 | number | 是 | 元，最多两位小数 | 未支付订单为应付金额 | 不允许为空 | `698.00` |

```json
{ "orderId": "9000001", "cancelType": "user", "cancelReason": "wrong_item", "cancelAmount": 698.00 }
```

### 6.18 order_refund 申请退款

**触发时机**：用户提交退款申请、服务端受理成功后记录。

**边界**：退款申请不等于退款到账。退款到账为服务端事件，本版本暂不纳入。

**属性**：

| 属性 | 含义 | 类型 | 必填 | 取值与格式 | 边界与说明 | 为空处理 | 示例 |
|---|---|---|---|---|---|---|---|
| `orderId` | 订单标识 | string | 是 | 字符串 | — | 不允许为空 | `9000001` |
| `refundId` | 退款单标识 | string | 是 | 字符串 | 退款单主键，与 `refund.refund_id` 对应，由服务端生成 | 不允许为空 | `66012` |
| `refundAmount` | 申请退款金额 | number | 是 | 元，最多两位小数 | 必须小于等于订单实付金额 | 不允许为空 | `698.00` |
| `refundType` | 退款类型 | string | 是 | 枚举：`refund_only`、`return_refund` | 仅退款 / 退货退款 | 不允许为空 | `return_refund` |
| `refundReason` | 退款原因 | string | 是 | 枚举：`no_need`、`quality_issue`、`wrong_item`、`not_as_described`、`other` | 枚举由服务端下发 | 不允许为空 | `quality_issue` |
| `skuIds` | 申请退款的 SKU 列表 | array | 是 | 字符串数组 | 部分退款时只包含申请退款的 SKU | 不允许为空数组 | `["12345"]` |

```json
{ "orderId": "9000001", "refundId": "66012", "refundAmount": 698.00, "refundType": "return_refund", "refundReason": "quality_issue", "skuIds": ["12345"] }
```

## 7. 属性规范

### 7.1 禁止重复携带公共字段

`properties` 中禁止出现 `baseInfo` 已有的字段，包括但不限于 `deviceId`、`userId`、`sessionId`、`appId`、`appVersion`、`pluginVersion`、`sendTime`、经纬度相关字段。端侧发现重复时按无效埋点处理。

### 7.2 标识类属性

本节的规则约束的是**上报报文中的取值形式**。实体在数据库中的存储类型以《交易域数据标准说明书 V1.0》为准，端侧只需在报文层把标识统一为字符串。

| 规则 | 说明 |
|---|---|
| 报文内一律使用 string | 所有 ID 在上报报文中一律为字符串，禁止用 number。JS 对超过 `2^53` 的整数存在精度丢失，订单号尤甚 |
| 取值来源 | 所有标识均取交易域实体的主键，对照关系见数据标准说明书第 9 节 |
| 端侧不得改写 | 端侧只能透传服务端下发的标识，不得拼接、截断或改写 |
| 空值与空字符串区分 | 未知用 `null`，禁止用 `""` |
| `productId` 与 `skuId` 不混用 | `productId` 指商品 SPU，`skuId` 指具体规格 SKU。订单、购物车、收藏等涉及规格的场景必须同时携带 `skuId` |

### 7.3 金额与币种

| 规则 | 说明 |
|---|---|
| 单位 | 统一为元 |
| 类型 | number，最多两位小数，禁止字符串 |
| 币种 | 每个金额属性所在的 `properties` 中必须有且仅有一个 `currency` |
| 精度 | 入库时按 `DECIMAL(18,2)` 处理，禁止使用浮点类型存储 |
| 金额闭合 | `order_submit` 必须满足 `payAmount = orderAmount - discountAmount + freightAmount` |

### 7.4 时间类属性

| 场景 | 规则 |
|---|---|
| 事件发生时间 | 使用 `eventInfo.eventTime`，不在 `properties` 中重复 |
| 业务时间（如 `payTime`） | ISO 8601 带时区，格式 `YYYY-MM-DDTHH:mm:ss.SSS+08:00` |
| 时长 | 使用毫秒整数，禁止秒或字符串 |
| 时区 | 统一使用东八区，禁止各端使用本地时区 |

### 7.5 枚举值

- 所有枚举值统一小写 snake_case。
- 枚举表由服务端统一下发，端侧不得自行扩展。
- 新增枚举值属于兼容变更，不需要修改 `eventType`，但必须同步更新本文档与服务端枚举表。
- 端侧遇到无法识别的枚举值时，`properties` 中对应字段写入 `other`，并将原始值写入 `baseInfo.extensions` 保留排查线索。

### 7.6 位置与曝光

`position` 命名格式为 `{模块}_{序号}`，序号从 1 开始。

| 示例 | 含义 |
|---|---|
| `recommend_1` | 推荐位第 1 个卡片 |
| `search_result_3` | 搜索结果第 3 个卡片 |
| `time_slot_2` | 限时活动第 2 个坑位 |
| `buy_box` | 详情页购买区，非列表场景可省略序号 |

同一商品在同一页面出现多次时，必须通过 `position` 区分，禁止合并为一条埋点。

### 7.7 数组类属性

- 空数组与 `null` 语义不同：空数组表示明确无内容，`null` 表示未知，两者不得混用。
- 数组内元素必须为同一类型，禁止混入 `null`。
- 数组长度上限为 100，超出时拆分为多条埋点记录。

## 8. 上报与重试口径

### 8.1 缓存与批量发送

事件触发后先生成本地事件对象并写入缓存，不立即发送到服务端。满足以下任一条件时触发一次发送：

| 触发条件 | 行为 |
|---|---|
| 缓存事件数达到 `cacheMaxLength` | 立即发送 |
| 首条缓存事件的等待时长达到 `cacheWaitingTime` | 发送当前已缓存的全部事件 |

| 参数 | 默认值 | 含义 |
|---|---|---|
| `cacheMaxLength` | 5 | 最大缓存事件数。缓存事件数达到该值时立即触发发送 |
| `cacheWaitingTime` | 5s | 延迟发送时长。首条事件进入缓存后等待超过该时长仍未达到 `cacheMaxLength` 时，发送已缓存的事件 |

发送时按 `cacheMaxLength` 为一批进行切分，分批发送，保证单个报文中的事件数不超过 `cacheMaxLength`。因此瞬时触发大量事件、缓存数超过 `cacheMaxLength` 时，会拆分为多个报文发出。

两个参数在各端必须取相同值。默认值可通过配置覆盖，但同一应用的所有端必须同步修改。

`cacheMaxLength = 5`、`cacheWaitingTime = 5s` 时的行为：

```
等待时长到期触发
12:00:00.000  第 1 条事件入缓存，等待计时开始
12:00:00.800  第 2 条事件入缓存
12:00:01.500  第 3 条事件入缓存
12:00:05.000  距首条事件满 5s，缓存仍为 3 条，立即发送这 3 条

缓存数达标触发
12:00:00.000  起连续产生 12 条事件
12:00:00.300  第 5 条产生，达到 cacheMaxLength，切出第 1 批 5 条发送
12:00:00.700  第 10 条产生，达到 cacheMaxLength，切出第 2 批 5 条发送
12:00:05.000  剩余 2 条等待 cacheWaitingTime 到期后发送
```

### 8.2 报文结构

一次上报为 1 个 `baseInfo` + N 个 `eventInfo`，其中 N 不超过 `cacheMaxLength`。`baseInfo` 取报文发出时刻的值，因此同一批事件共享同一份 `baseInfo`，但各自保留自己的 `eventTime`。

### 8.3 失败重试

| 项目 | 口径 |
|---|---|
| 重试策略 | 指数退避重试，最多 3 次 |
| 重试失败 | 写入本地持久队列，等待下次发送时机重试 |
| 本地队列上限 | 10000 条或 7 天，先到者为准 |
| 超出上限的丢弃优先级 | 先丢 `product_expose`、`page_view`；交易类事件与 `app_launch` 最后丢弃 |
| 补传 | 补传时 `eventTime` 保留事件原始发生时间，`sendTime` 为实际发送时间 |
| 幂等去重 | 服务端按 `eventId` 去重，重复上报只保留首条 |
| 上报开关 | 用户关闭埋点采集后立即停止上报，本地缓存与队列清空且不再落盘 |

应用退出时若缓存中仍有未发送的事件，必须先触发一次发送再退出，不等待 `cacheWaitingTime` 到期。进程被系统强杀导致缓存丢失的情形无法避免，丢失率纳入数据质量监控。

## 9. 合规要求

| 要求 | 说明 |
|---|---|
| 告知同意 | 采集前明确告知用途，取得用户授权 |
| 最小必要 | 只采集业务必需的行为数据，禁止为采集而采集 |
| 目的限制 | 不得超范围使用或违规向第三方提供 |
| 禁止采集输入内容 | 不采集任何输入框的原始文本，包括密码、手机号、身份证号、地址、聊天内容 |
| 搜索词脱敏 | `search_submit.keyword` 发送前做脱敏过滤，命中手机号、身份证号、银行卡号时替换为占位符 |
| URL 去参 | `pageUrl` 必须剔除 `token`、`session`、`phone`、`email` 等敏感查询参数后再记录 |
| 禁止采集剪贴板 | 不采集剪贴板内容与设备通讯录 |
| 地理位置 | 经纬度属于敏感个人信息，需单独告知并取得同意，加密存储，且满足第 4.1 节的采集约束 |
| 访问审计 | 记录谁在何时读取了位置数据 |
| 未成年人保护 | 不采集可用于识别未成年人身份的行为特征 |
| 上报开关可见 | 应用内必须提供关闭埋点采集的入口，关闭后行为埋点与设备标识一并停止采集 |
| 数据安全 | 敏感字段加密或脱敏存储，权限最小化 |
| 保留期限 | 原始数据保留期按合规要求设定，到期删除或匿名化 |

## 10. 易混淆对照表

| 易混淆对 | 区别 |
|---|---|
| `product_expose` vs `product_view` | 列表或推荐位露出，未进入详情页 vs 已进入详情页并可见 |
| `product_click` vs `product_view` | 点击卡片触发跳转 vs 详情页渲染完成。点击后加载失败时只有前者 |
| `page_view` vs `product_view` | 通用页面浏览 vs 商品详情页特化，两者会同时产生，分析时取其一 |
| `button_click` vs 专属事件 | 无专属事件的按钮 vs 已定义专属事件的按钮，后者必须用专属事件 |
| `favorite_add` vs `cart_add` | 收藏为长期意向，加购为短期成交意向，两者不可互相代替 |
| `cart_add` vs `order_submit` | 加购不产生订单，下单产生 `orderId` 并锁定库存 |
| `order_submit` vs `order_pay` | 订单创建成功 vs 支付渠道确认收款，两者之间可能因取消或超时而中断 |
| `order_cancel` vs `order_refund` | 未支付订单取消 vs 已支付订单申请退款 |
| `orderAmount` vs `payAmount` | 优惠前商品总价 vs 实际应付/实付金额 |
| `productId` vs `skuId` | 商品 SPU vs 具体规格 SKU，涉及规格的场景必须同时携带 |
| `searchId` vs `sessionId` | 一次搜索请求 vs 一次会话，前者生命周期短于后者 |
| `eventTime` vs `payTime` | 埋点记录时间 vs 支付业务发生时间，补传时差异明显 |
| `eventTime` vs `sendTime` | 事件实际发生时间 vs 报文发送时间，补传时差异明显 |
| `position` vs `source` | 页面内的展示位置 vs 进入当前页面的来源渠道 |

## 11. 埋点验收

### 11.1 上线前检查项

1. 全部 `eventType` 已在埋点管理平台登记，`eventName` 与本文档一致。
2. `properties` 字段名、类型、枚举值与本文件一致，无端侧自造字段。
3. 必填属性缺失时不产生记录，且在调试日志中可见丢弃原因。
4. `pageUrl`、`keyword` 的脱敏逻辑已生效，抽样验证无敏感信息。
5. 各端对同一动作采出的 `eventType` 与属性集合一致。
6. 各端 `cacheMaxLength` 与 `cacheWaitingTime` 取值一致，且与配置下发值相符。

### 11.2 必测边界用例

| 事件 | 用例 | 预期结果 |
|---|---|---|
| `app_launch` | 冷启动后切后台再恢复 | 记录两条，`launchType` 分别为 `cold`、`warm` |
| `app_exit` | 应用切至后台 | 不记录 |
| `page_view` | 页面加载失败出现白屏 | 不记录 |
| `page_view` / `page_leave` | 连续跳转三个页面 | 三次 `page_view` 与三次 `page_leave` 成对，`pageId` 一一对应 |
| `page_leave` | 切后台超过 30 分钟 | 记录一条，`leaveType` 为 `background` |
| `product_expose` | 卡片快速滑过，可见不足 500ms | 不记录 |
| `product_expose` | 同一卡片在 5 秒内反复进出视口 | 只记录一条 |
| `product_click` | 点击卡片后详情页加载失败 | 只有 `product_click`，无 `product_view` |
| `product_view` | 同一次进入内下拉刷新 | 不重复记录 |
| `button_click` | 点击加购按钮 | 记录 `cart_add`，不记录 `button_click` |
| `search_submit` | 仅输入关键词未提交 | 不记录 |
| `search_submit` | 关键词为手机号 | 记录的 `keyword` 为脱敏占位符 |
| `favorite_add` | 未登录被引导至登录页 | 不记录 |
| `cart_add` | 一次加入两个 SKU | 记录两条，`skuId` 不同 |
| `cart_add` | `quantity` 传 0 | 视为非法埋点，不记录 |
| `order_submit` | 库存不足下单失败 | 不记录 |
| `order_submit` | 正常下单 | `payAmount = orderAmount - discountAmount + freightAmount` 成立 |
| `order_pay` | 用户调起支付后取消 | 不记录 |
| `order_pay` | 支付渠道重复回调 | 只记录一条 |
| `order_pay` | 服务端延迟补传 | `eventTime` 晚于 `payTime`，`eventTime` 仍为原始发生时间 |
| `order_cancel` | 超时未支付自动取消 | 记录一条，`cancelType` 为 `timeout` |
| `order_refund` | 退款金额大于订单实付金额 | 视为非法埋点，不记录 |
| 通用 | 报文中 `properties` 出现 `deviceId` | 视为无效埋点，服务端丢弃并告警 |
| 通用 | ID 字段记录为 number 类型 | 视为类型错误，服务端按字符串解析并告警 |
| 通用 | 距离上次事件 31 分钟后产生事件 | 新建 `sessionId`，与前一事件不同 |
| 通用 | 产生 3 条事件后不再操作，等待至 `cacheWaitingTime` 到期 | 这 3 条合并为一个报文发送，此时不等待满 `cacheMaxLength` |
| 通用 | 连续产生 7 条事件，间隔小于 `cacheWaitingTime` | 第 5 条触发第一个报文（5 条），剩余 2 条在 `cacheWaitingTime` 到期后发送 |
| 通用 | 缓存中尚有 2 条时用户关闭应用 | 立即触发一次发送后再退出，不等待 `cacheWaitingTime` |
| 通用 | 报文中的事件数 | 不超过 `cacheMaxLength` |

### 11.3 上线后数据校验

| 校验项 | 口径 |
|---|---|
| 漏斗一致性 | 同一 `sessionId` 下 `order_submit` 数量不得大于 `cart_add` 数量 |
| 链路完整性 | 每条 `order_pay` 均能在前 7 天内找到 `orderId` 相同的 `order_submit` |
| 字段完整率 | 必填属性完整率应为 100%，非必填属性完整率低于 60% 时需评估是否应收窄口径 |
| 时间单调性 | 同一 `orderId` 的 `order_submit.eventTime` 不晚于 `order_pay.eventTime` |
| 金额一致性 | `order_pay.payAmount` 与 `order_submit.payAmount` 的差异率超过 5% 时需核查 |
| 会话切分 | 同一 `sessionId` 内相邻事件的间隔不得大于 30 分钟 |
| 枚举越界 | 出现枚举表外的值时告警，并按 `other` 归档 |

## 12. 使用约定

- 行为埋点的采集必须严格按本说明书执行，新增埋点不得先于口径定义上线。
- 新增事件或属性必须补充采集口径并升级本文档版本，禁止端侧先行定义。
- 枚举值新增属于兼容变更，需同步更新枚举表；`eventType` 变更属于不兼容变更，需评估下游影响并保留双写周期。
- 上线前必须完成第 11.1 与 11.2 节的全部检查项，验收记录留存。
- 测试用例必须覆盖边界条件，尤其是 `product_expose` 曝光阈值、`product_click` 与 `product_view` 的区分、`order_submit` 与 `order_pay` 的金额口径、以及全部 ID 字段的类型。
